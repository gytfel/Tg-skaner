# Tg-skaner

Userbot на [Telethon](https://docs.telethon.dev/), который сохраняет **удалённые и
изменённые сообщения в ваших собственных чатах**. Работает на вашем аккаунте
через `api_id` / `api_hash` — отдельный бот-аккаунт не нужен.

Когда кто-то (или вы сами) удаляет сообщение в переписке с вами, Telegram
присылает лишь сигнал «удалить» без содержимого. Tg-skaner заранее держит
локальную копию каждого проходящего сообщения, поэтому в момент удаления может
переслать оригинал вам в «Избранное».

## Что умеет

- 🗑 Показывает удалённые сообщения (с обеих сторон — ваши и собеседника).
- ✏️ Фиксирует правки сообщений в формате «было / стало».
- 📎 Восстанавливает медиа (фото, видео, документы), если включён `SAVE_MEDIA`.
- 🧹 Автоматически чистит старый кэш (срок задаётся в `RETENTION_DAYS`).
- 📨 Шлёт все уведомления в выбранный чат (по умолчанию — ваше «Избранное»).

## Как это работает и где границы

Это **архиватор того, что реально дошло до вашего аккаунта**, пока бот запущен.
Он не читает чужие устройства, не вытаскивает сообщения, которых ваш аккаунт не
получал, и не работает «задним числом». Он просто хранит вашу копию того, что
вам прислали, до того как оно будет стёрто.

> ⚠️ Используйте только для своего аккаунта и своих переписок. Собеседники в
> общих чатах могут не знать, что вы храните копии их сообщений — это ваша
> ответственность и зависит от законов вашей страны. Запуск на чужом аккаунте
> без согласия владельца недопустим.

## Установка

Нужен Python 3.10+.

```bash
git clone <этот-репозиторий>
cd Tg-skaner

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Настройка

1. Откройте https://my.telegram.org → **API development tools** и создайте
   приложение. Скопируйте `api_id` и `api_hash`.
2. Создайте файл настроек из шаблона и впишите значения:

   ```bash
   cp .env.example .env
   # откройте .env и заполните API_ID и API_HASH
   ```

Параметры `.env`:

| Переменная        | По умолчанию | Описание                                                           |
|-------------------|--------------|--------------------------------------------------------------------|
| `API_ID`          | —            | ID приложения с my.telegram.org                                    |
| `API_HASH`        | —            | Hash приложения с my.telegram.org                                  |
| `SESSION_NAME`    | `tg_skaner`  | Имя файла сессии Telethon                                          |
| `LOG_CHAT`        | `me`         | Куда слать отчёты: `me`, `@username` или числовой id чата          |
| `SAVE_MEDIA`      | `true`       | Сохранять медиа, чтобы восстановить после удаления                 |
| `RETENTION_DAYS`  | `7`          | Сколько дней хранить кэш сообщений и медиа                         |
| `IGNORE_OUTGOING` | `false`      | `true` — не трогать ваши исходящие; `false` — фиксировать обе стороны |

## Запуск

```bash
python bot.py
```

При **первом** запуске Telethon спросит номер телефона, код из Telegram и, если
включена двухфакторная аутентификация, пароль. Дальше вход сохранится в файл
`*.session`, и повторно спрашивать не будет.

Готово: держите скрипт запущенным (на ПК, сервере или в `tmux`/`screen`), и все
удаления и правки будут прилетать в ваше «Избранное».

## Файлы

| Файл             | Назначение                                      |
|------------------|-------------------------------------------------|
| `bot.py`         | Точка входа и обработчики событий Telethon       |
| `config.py`      | Чтение настроек из `.env`                         |
| `db.py`          | Кэш сообщений на SQLite                           |
| `messages.db`    | Локальная база (создаётся автоматически)          |
| `media/`         | Скачанные вложения (создаётся автоматически)      |
| `*.session`      | Файл сессии Telegram (секрет — не публиковать!)   |

`.env`, `*.session`, `messages.db` и `media/` добавлены в `.gitignore` —
не коммитьте их.

## А как же Telegram Business?

В Telegram Business к **бизнес-аккаунту** можно подключить обычного бота (по
bot-токену), и он получает апдейты по вашим чатам. Это другая модель авторизации
(бот-токен вместо пользовательской сессии) и требует платной подписки Premium с
включённым Business. Для задачи «видеть удалённые сообщения в своих чатах»
userbot-подход выше самодостаточен и не требует Business — поэтому он и выбран.
