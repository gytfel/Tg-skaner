# Tg-skaner

Userbot на [Telethon](https://docs.telethon.dev/), который архивирует **ваши
переписки вместе с удалёнными и изменёнными сообщениями** и присылает их вам
**в отдельного Telegram-бота**. Захват работает на вашем аккаунте через
`api_id` / `api_hash`; доставка — через бота (токен от @BotFather).

Когда кто-то (или вы сами) удаляет сообщение в переписке с вами, Telegram
присылает лишь сигнал «удалить» без содержимого. Tg-skaner заранее держит
локальную копию каждого проходящего сообщения, поэтому удалённый текст и медиа
не теряются.

## Что умеет

- 🤫 **Тихий режим (по умолчанию):** бот ничего не пишет — только присылает
  zip-файл переписок, когда архив накопит `EXPORT_LIMIT_MB`, и после доставки
  чистит данные на сервере. Запустили — и он работает пассивно.
- 🗑 Фиксирует удалённые сообщения (с обеих сторон — ваши и собеседника).
- ✏️ Фиксирует правки сообщений в формате «было / стало».
- 📎 Сохраняет медиа (фото, видео, документы), если включён `SAVE_MEDIA`.
- 🔔 По желанию (`PASSIVE_MODE=false`) — каждое удаление/правка сразу приходит
  отдельным сообщением.

## Как это работает и где границы

Это **архиватор того, что реально дошло до вашего аккаунта**, пока бот запущен.
Он не читает чужие устройства, не вытаскивает сообщения, которых ваш аккаунт не
получал, и не работает «задним числом». Он просто хранит вашу копию того, что
вам прислали, до того как оно будет стёрто.

> ⚠️ Используйте только для своего аккаунта и своих переписок. Собеседники в
> общих чатах могут не знать, что вы храните копии их сообщений — это ваша
> ответственность и зависит от законов вашей страны. Запуск на чужом аккаунте
> без согласия владельца недопустим.

## Подготовка (один раз)

1. **API-ключи.** Откройте https://my.telegram.org → **API development tools**,
   создайте приложение, скопируйте `api_id` и `api_hash`.
2. **Бот.** Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`,
   придумайте имя — получите `BOT_TOKEN`.

## Установка на VPS через терминал (рекомендуется)

Автоматический скрипт поставит зависимости, выполнит вход и настроит автозапуск
через **systemd** (бот будет работать 24/7 и переживёт перезагрузку сервера).

На свежем сервере (Ubuntu/Debian), подключившись по SSH:

```bash
apt update && apt install -y git
git clone -b claude/telegram-deleted-messages-bot-ovwzus --single-branch \
  https://github.com/gytfel/Tg-skaner.git
cd Tg-skaner
bash install.sh          # не под root — добавьте sudo: sudo bash install.sh
```

> После слияния ветки в `main` клонировать можно обычным
> `git clone https://github.com/gytfel/Tg-skaner.git` без `-b ...`.

Скрипт спросит `API_ID`, `API_HASH`, `BOT_TOKEN`, затем номер телефона и код из
Telegram (и 2FA-пароль, если включён). После установки:

```bash
systemctl status tg-skaner      # состояние
journalctl -u tg-skaner -f      # живые логи
systemctl restart tg-skaner     # перезапуск
systemctl stop tg-skaner        # остановка
```

Напоследок откройте вашего бота в Telegram и нажмите **Start** — и отчёты пойдут.

## Запуск вручную (локально / для теста)

Нужен Python 3.10+.

```bash
git clone -b claude/telegram-deleted-messages-bot-ovwzus --single-branch \
  https://github.com/gytfel/Tg-skaner.git
cd Tg-skaner

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp env/.env.example env/.env       # впишите API_ID, API_HASH, BOT_TOKEN
python login.py                    # одноразовый вход (создаст *.session)
python bot.py                      # запуск; держите процесс живым
```

Чтобы процесс не умирал при закрытии SSH — используйте `tmux`/`screen` или
вариант с systemd выше.

## Параметры `env/.env`

| Переменная        | По умолчанию | Описание                                                            |
|-------------------|--------------|---------------------------------------------------------------------|
| `API_ID`          | —            | ID приложения с my.telegram.org                                     |
| `API_HASH`        | —            | Hash приложения с my.telegram.org                                   |
| `BOT_TOKEN`       | —            | Токен бота от @BotFather. Задан → отчёты шлются в бота               |
| `OWNER_ID`        | авто         | Кому слать (числовой id); учитывается только при заданном `BOT_TOKEN`. По умолчанию — ваш аккаунт |
| `SESSION_NAME`    | `tg_skaner`  | Имя файла сессии Telethon                                           |
| `LOG_CHAT`        | `me`         | Куда слать, если `BOT_TOKEN` пуст: `me`, `@username` или id          |
| `SAVE_MEDIA`      | `true`       | Сохранять медиа, чтобы восстановить после удаления                  |
| `RETENTION_DAYS`  | `7`          | Сколько дней хранить кэш `messages.db` (медиа при экспорте удаляется только после доставки) |
| `IGNORE_OUTGOING` | `false`      | `true` — не трогать ваши исходящие; `false` — обе стороны            |
| `EXPORT_ENABLED`  | `true`       | Включить автоэкспорт архива копий в бота по лимиту размера           |
| `EXPORT_LIMIT_MB` | `100`        | При каком объёме (архив + `media/`) паковать и выгружать (МБ)        |
| `PASSIVE_MODE`    | `true`       | Тихий режим: никаких сообщений, только zip-файл переписок            |
| `MAX_MEDIA_MB`    | `50`         | Не качать вложения больше этого размера (МБ); `0` — без ограничения  |
| `MIN_FREE_MB`     | `1024`       | Сколько места всегда оставлять свободным; ниже — вложения не качаются |
| `ARCHIVE_CHANNELS`| `false`      | `true` — архивировать и каналы-ленты (по умолчанию только личные чаты и группы) |

## Автоэкспорт архива и тихий режим

Все проходящие сообщения, а также события «изменено» и «удалено» пишутся
одной строкой JSON в `export/archive.jsonl`. Когда суммарный объём «архив +
папка `media/`» достигает `EXPORT_LIMIT_MB` (по умолчанию 100 МБ):

1. всё пакуется в один `zip`:
   - `переписки/<чат> (<id>).txt` — читаемые переписки, по файлу на чат,
     с пометками `✏️ изменил(а)` (было/стало) и `🗑 УДАЛЕНО`;
   - `media/` — вложения;
   - `raw/*.jsonl` — исходные записи (для программ);
2. бот присылает этот `zip` вам в Telegram (в подписи — сколько сообщений,
   удалений и правок внутри);
3. **только после успешной доставки** архив и медиа на сервере удаляются —
   диск освобождается. Если отправить не вышло, данные остаются и отправка
   повторяется позже.

В тихом режиме (`PASSIVE_MODE=true`, по умолчанию) этот файл — единственное, что
пишет бот. Хотите получать файлы чаще — уменьшите `EXPORT_LIMIT_MB` (например, 20).

На сервере остаётся только небольшая база `messages.db` (текст без медиа): она
нужна, чтобы при удалении узнать, *что именно* удалили, и сама чистится по
`RETENTION_DAYS`.

> Лимит стоит держать ниже ~1900, т.к. Telegram ограничивает размер одного файла.

### Защита диска

* Один zip никогда не больше `EXPORT_LIMIT_MB`: если медиа накопилось больше,
  оно уходит несколькими файлами подряд (от старых к новым). Поэтому для сборки
  архива не нужно много свободного места.
* Вложения больше `MAX_MEDIA_MB` не скачиваются — в переписке остаётся пометка
  `[медиа не сохранено: …]`. Каналы-ленты по умолчанию не архивируются.
* Если свободно меньше `MIN_FREE_MB`, новые вложения не качаются (текст
  продолжает писаться), а накопленное выгружается, не дожидаясь лимита.
* Если диск всё же почти заполнен (< 150 МБ), бот удаляет самые старые
  вложения и пишет об этом в лог, чтобы не остановиться совсем.
* Зависшая выгрузка обрывается по таймауту и повторяется позже.

### Если бот «заглох»

Бот сам проверяет связь с Telegram каждые 5 минут. Если связи нет 15 минут или
событий нет 4 часа, он завершается, и systemd перезапускает его. Проверить
состояние можно командой **`/status`** в боте: время работы, последнее событие,
свободное место, объём, ждущий выгрузки, и время последнего экспорта.

```bash
df -h /                                          # сколько места на диске
du -sh ~/Tg-skaner/{media,media_tmp,export,messages.db}  # что занимает место
journalctl -u tg-skaner -n 100 --no-pager        # последние строки лога
```

## А как же Telegram Business?

В Telegram Business к **бизнес-аккаунту** можно подключить обычного бота по
bot-токену, и он получает апдейты по вашим чатам, но это другая модель
авторизации и требует подписки Premium с включённым Business. Для задачи «видеть
удалённые сообщения в своих чатах» userbot-подход выше самодостаточен и не
требует Business — поэтому он и выбран.
